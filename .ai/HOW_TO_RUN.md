# কীভাবে চালাবেন — ধাপে ধাপে

> এই একটি ফাইল পড়লেই সব বোঝা যাবে। অন্য কোনো ফাইল আপনার পড়ার দরকার নেই।

---

## এক নজরে

আপনার কাজ মাত্র তিনটি:

```
১. .ai/prompts/ ফোল্ডার থেকে একটি .txt ফাইল খুলুন
২. পুরো ফাইল কপি করুন  (Ctrl+A → Ctrl+C)
৩. মডেলের চ্যাটে পেস্ট করুন  (Ctrl+V → Enter)
```

**"কোথা থেকে কতটুকু কপি করব" — এই প্রশ্নই আর নেই।** প্রতিটি ফাইলের পুরোটাই
কপি করবেন। ভেতরে বুট নির্দেশনা, নিয়ম, টাস্ক — সব একসাথে বসানো আছে।

### 🔴 প্রতিটি BULK প্রম্পটের জন্য নতুন টাস্ক খুলবেন

পুরনো টাস্কে ফিরে গিয়ে চালিয়ে যাবেন না। কারণ:

- লম্বা কনভার্সেশনে প্রতিটি মেসেজে পুরো হিস্টরি আবার পাঠানো হয় → টোকেন
  দ্রুত ফুরায়
- কনটেক্সট ভরে গেলে Cline নিজেই মাঝের অংশ কেটে ফেলে → "কোন ফাইল শেষ
  হয়েছে" ঠিক সেই তথ্যই হারায়

নতুন টাস্কে মডেল `git log` + `PROGRESS.md` + `.ai/reports/` পড়ে নিজেই জেনে
যাবে কোথায় থেমেছিল। **হিস্টরির দরকার নেই।**

### মডেল প্রথমে যা বলবে

প্রম্পট দেওয়ার পর মডেল একটি লাইন বলবে, যেমন:

```

```

অথবা মাঝপথে বন্ধ হয়ে আবার শুরু করলে:


**এই লাইনটি পড়ে নিন।** ভুল বললে (যেমন শেষ হয়ে যাওয়া টাস্কে আবার ঢুকছে)
শুধু লিখুন: `না, PROGRESS.md আবার দেখো।`

## মডেল প্রজেক্ট সম্পর্কে কিছুই জানে না — সমস্যা হবে না?

স্বাভাবিক প্রশ্ন। উত্তর: **না, সমস্যা হবে না** — কারণ প্রম্পট মডেলকে জ্ঞান
দেয় না, **জ্ঞান কোথায় পাবে সেই ঠিকানা** দেয়।

প্রম্পটের প্রথম ধাপেই লেখা আছে:

```
১. পড়ো:  .ai/PROJECT_CONTEXT.md
২. পড়ো:  .ai/PROGRESS.md
৩. চালাও: git log --oneline -20
৪. চালাও: git status --short
```

মডেল এই চারটি করার পর সে জেনে যায়:

| কী জানে | কোথা থেকে |
|---|---|
| Laravel 11, multi-store SaaS, ৩টি theme | PROJECT_CONTEXT.md |
| ৫০৮ blade, ১৩৩ controller, ৮০ model | PROJECT_CONTEXT.md |
| ৮টি চিহ্নিত সমস্যা (P1–P8) কোন ফাইলে | PROJECT_CONTEXT.md |
| কোন ফোল্ডার নিষিদ্ধ, কেন | PROJECT_CONTEXT.md |
| কোন টাস্ক শেষ, কোনটা বাকি | PROGRESS.md |
| আসলে কী কাজ হয়েছে | git log |

এরপর টাস্ক প্রম্পটে থাকে **ঠিক কোন ফোল্ডারে কাজ করবে** — যেমন
`themes/stylique/views/**/*.blade.php`। মডেল ওই ফাইলগুলো নিজে পড়ে নেয়।

### তিনটি জিনিস যা এটা সম্ভব করে

**১. মডেলের ফাইল পড়ার ক্ষমতা আছে।** Cline, Antigravity — এগুলো মডেলকে
ফাইল পড়তে ও কমান্ড চালাতে দেয়। তাই "না জানা" অবস্থা মাত্র কয়েক সেকেন্ড
থাকে, তারপর সে নিজেই পড়ে নেয়।

**২. টাস্ক ছোট ও নির্দিষ্ট।** কোনো মডেলকে "পুরো প্রজেক্ট বোঝো" বলা হচ্ছে না।
BULK-1 এর পুরো কাজ হলো `<img>` ট্যাগে দুটো attribute যোগ করা — এর জন্য
Laravel জানার দরকার নেই।

**৩. যা জানার দরকার নেই, সেটা প্রম্পট আগেই সিদ্ধান্ত নিয়ে রেখেছে।** কোন
theme, কোন ফোল্ডার, কোন ব্যতিক্রম, কী commit message — সব লেখা আছে। মডেলকে
কিছু অনুমান করতে হয় না।

| আপনি | কখন GitHub-এ পাঠাবেন সেটা ঠিক করেন |

**কোনো মডেল নিজে থেকে push করবে না।** এটা ইচ্ছাকৃত, এবং তিনটি প্রম্পট
ফাইলেই লিখে দেওয়া আছে।

### কেন মডেলকে push করতে দিচ্ছি না

repo-টি **public** — যে কেউ দেখতে পারে। এখন কোনো মডেল ভুলে একটি পাসওয়ার্ড
বা API key কোনো ফাইলে লিখে commit করে ফেললে:

```
শুধু commit হয়েছে   →  ঠিক করা যায়, কেউ দেখেনি
push হয়ে গেছে      →  GitHub-এর ইতিহাসে স্থায়ী, মুছলেও থেকে যায়
```

তাই push-এর আগে সবসময় একটি মানুষের সিদ্ধান্ত থাকবে।

### push করতে চাইলে

আমাকে শুধু বলবেন **"GitHub-এ পাঠাও"**। আমি আগে যাচাই করব:

```
১. অপ্রত্যাশিত কোনো ফাইল যাচ্ছে কি না
২. .env বা কোনো পাসওয়ার্ড-জাতীয় ফাইল ঢুকেছে কি না
৩. কী কী commit যাচ্ছে তার তালিকা দেখাব
```

তারপর push করব। প্রথমবার GitHub আপনার লগইন চাইতে পারে (ব্রাউজার খুলবে
অথবা টোকেন চাইবে) — সেটা আপনাকেই দিতে হবে, আমি পারব না।

### Day 0-এ যা যাচাই করা হয়েছে

```
✅ .env ফাইল git-এ নেই (আপনার ডেটাবেস পাসওয়ার্ড নিরাপদ)
✅ .env.example এ সব মান খালি বা "null"
✅ vendor/ (১৭৭ MB), node_modules/ (৩৯ MB) বাদ দেওয়া
✅ ব্যবহারকারীর আপলোড করা ছবি বাদ দেওয়া
✅ ট্র্যাক করা: ৩,০৮২ ফাইল / ~১৫৬ MB
```

### একটি ছোট বিষয়

GitHub-এ repo-টি এখন খালি, আর তার ডিফল্ট ব্রাঞ্চের নাম `main`। আমাদের
লোকাল ব্রাঞ্চের নাম `master`। প্রথম push-এ `master` নামেই যাবে — কোনো
সমস্যা হবে না, শুধু GitHub-এ দুইটি নাম দেখতে পাবেন। চাইলে আমি `main`
নামে পাঠাতে পারি, বললেই হবে।

সব ফেরানোর কমান্ড — আমাকে বললেই চালিয়ে দেব:

| কতটুকু ফেরাতে চান | কমান্ড |
|---|---|
| একদম শুরুর অবস্থা | `git reset --hard baseline-v0` |
| Day 1 শেষের অবস্থা | `git reset --hard day1-complete` |
| Day 2 শেষের অবস্থা | `git reset --hard day2-complete` |

এছাড়া প্রতিটি ফিচারের একটি **kill-switch** আছে — `.env` ফাইলে এক শব্দ
বদলালে সেই ফিচার বন্ধ হয়ে পুরনো আচরণ ফিরে আসে। কোনো কিছু ভাঙলে আমাকে
বলবেন, আমি বন্ধ করে দেব।
